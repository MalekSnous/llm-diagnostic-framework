📊 LLM Diagnostic Framework

A systematic way to diagnose LLM failures and benchmark prompt engineering, RAG and fine-tuning by cost and performance — measuring, not guessing.

View on GitHub Browse the reports

The thesis: optimization is task-dependent — so measure

Prompt engineering, RAG and fine-tuning each help on some tasks and hurt on others. This framework benchmarks quality vs cost under one harness so the trade-off is explicit.

  • 📊 Measure the baseline first — optimization is not a free lunch.
  • ❌ Generic strategies can hurt a model already strong at the task.
  • ✅ RAG wins when the answer is outside the model's knowledge — and hurts when it just adds noise.
  • 💰 Judge cost per quality point, not raw accuracy or raw price.
  • 🔬 Trust the metric, not the vibe — entity extraction is scored with precision/recall/F1, so a verbose model can't win by dumping text.

Concrete numbers are intentionally produced by running the studies (below) — re-run them with your own models/keys to get figures you can trust.

How to run the studies →

Try it in 30 seconds

The test suite is fully offline (mocked LLM client) — no API key needed to run it.

git clone https://github.com/MalekSnous/llm-diagnostic-framework.git
cd llm-diagnostic-framework
pip install -e ".[dev]"
make test                      # offline, no cost

# Run the RAG document-QA study (needs an API key)
pip install -e ".[rag]"
make run-rag-study model=gpt-4o-mini
