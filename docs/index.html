📊 LLM Diagnostic Framework

A systematic way to diagnose LLM failures and benchmark prompt engineering, RAG and fine-tuning by cost and performance — measuring, not guessing.

The thesis: optimization is task-dependent — so measure

Prompt engineering, RAG and fine-tuning each help on some tasks and hurt on others. This framework benchmarks quality vs cost under one harness so the trade-off is explicit.

  • 📊 Measure the baseline first — optimization is not a free lunch.
  • ❌ Generic strategies can hurt a model already strong at the task.
  • ✅ RAG wins when the answer is outside the model's knowledge — and hurts when it just adds noise.
  • 💰 Judge cost per quality point, not raw accuracy or raw price.
  • 🔬 Trust the metric, not the vibe — entity extraction is scored with precision/recall/F1, so a verbose model can't win by dumping text.
  • 🧪 Prefer executable metrics when you can get them — the text-to-SQL study runs the generated query and compares result sets, so the score can't be gamed at all.

Concrete numbers are intentionally produced by running the studies (below) — re-run them with your own models/keys to get figures you can trust.

Medical Entity Extraction

When generic RAG and few-shot prompting degrade an already-strong model.

Clinical note
“Pt c/o chest pain radiating to L arm. Hx of HTN. Started aspirin 81 mg daily.”
LLM
Extracted entities
{"conditions": ["chest pain", "hypertension"], "medications": ["aspirin 81 mg"]}
scored
F1 vs gold
precision & recall against gold annotations → F1

Verbosity can't win: every extra made-up entity costs precision, every missed one costs recall.

RAG · Document QA

Document QA with RAG

The opposite case: questions about a private knowledge base the model was never trained on — retrieval is what unlocks accuracy.

Question
“How much is each additional ACU billed at on the Growth plan?”
retrieve
Retrieved chunk
[source: plans_and_billing] …The Growth plan includes 500 free ACUs per month, with additional ACUs billed at $0.08 each…
LLM
Grounded answer
“$0.08 per additional ACU [plans_and_billing]”

Closed-book, the model can only guess (the facts are private). The study scores retrieval recall@k and answer accuracy separately — and unanswerable questions must get “Not in the documentation”, not a hallucination.

Text-to-SQL

Text-to-SQL with Execution

The generated SQL is executed — a metric you can't game with verbosity.

Question
“List the names of customers who never placed an order.”
LLM
Generated SQL
SELECT name FROM customers WHERE id NOT IN ( SELECT customer_id FROM orders);
executed
Execution check
result rows == gold rows → 1 point, else 0

Both the model's query and the gold query run on the same seeded SQLite database; only matching result sets score. Formatting, aliases and row order don't matter — correctness does.

Try it in 30 seconds

The test suite is fully offline (mocked LLM client) — no API key needed to run it.

git clone https://github.com/MalekSnous/llm-diagnostic-framework.git
cd llm-diagnostic-framework
pip install -e ".[dev]"
make test                      # offline, no cost

# Run the RAG document-QA study (needs an API key)
pip install -e ".[rag]"
make run-rag-study model=gpt-4o-mini
